# macOS and Browser Functional Parity

This matrix is the release checklist for ADR 0004. Parity means equivalent
resource semantics, safety, and workflow completion using native macOS
interaction. It does not mean React component or pixel parity.

Status values:

- Complete: implemented and covered by an automated or named acceptance test.
- Partial: a usable slice exists, but one or more baseline workflows are absent.
- Missing: no usable native workflow exists.

## Connection and window architecture

| Capability | Status | Acceptance evidence |

| Local-managed Runtime profile | Complete | Launch and reconnect work; optional Files/Git projections load independently so host authorization cannot block Sessions or Terminals. | HTTPS-attached Runtime profile | Complete | Native profile setup requires a named HTTPS endpoint with a host and non-empty bearer before Add Server becomes available. ## Release readiness rule

A macOS release is ready for distribution only after every required row is
Complete. Accepting ADR 0004 records the workstation-scope decision and does
not waive this release gate. Any intentional product difference must be
documented in a superseding ADR, not silently marked Complete.
